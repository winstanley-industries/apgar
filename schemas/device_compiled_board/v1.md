# DeviceCompiledBoard Contract v1

DeviceCompiledBoard v1 is the immutable, backend-neutral Phase 2 upload form
derived from `CompiledBoard` v1. It describes planar H/V/45 search semantics;
it is not an exact-geometry authority and does not add layer transitions.

## Associations and versioning

The header records schema version `1`, the source Board IR content hash,
compiler-profile fingerprint, geometry-compiler version, rule-bucket identity,
and a device-view fingerprint. Upload is rejected unless the CompiledBoard
associations match the exact BoardSnapshot. A 56-byte result header is produced
on the device from the uploaded header and repeats every association, endpoint
node, and forced generator. Readback is rejected before interpretation when
any value differs; host-side stamping cannot self-certify a stale device result.

The device-view fingerprint is FNV-1a over the domain tag
`APGAR-DEVICE-COMPILED-BOARD-V1` and the canonical header, layer, node, run, and
run-node fields in schema order. The fingerprint excludes its own value.

## Stable node and state indices

Nodes retain CompiledBoard tile order `(layer, tile_x, tile_y)` and sorted local
row-major order within each sparse tile. Flattening assigns consecutive
unsigned 32-bit node indices in that order. Missing sparse nodes remain absent;
no bounding-box placeholders are synthesized.

Every node stores signed 64-bit lattice coordinates, layer, legal-direction
mask, and eight neighbor node indices in east-through-south-east order. An
absent neighbor is `UINT32_MAX`. A set mask bit and its neighbor index must
agree, the neighbor must be adjacent on the same layer, and every edge must
have its compiled reverse edge.

Each node owns nine stable heading states:

```text
state_index = node_index * 9 + incoming_heading
```

Incoming headings `0..7` use the CompiledBoard direction numbering. Heading
`8` is the no-incoming-heading sentinel and is finite only for the start node.
The maximum CompiledBoard v1 node count therefore fits all state indices below
the `UINT32_MAX` invalid sentinel.

Layer records give an explicit node offset/count and inclusive signed lattice
bounds. Bounds describe represented samples only; they are neither an inferred
board outline nor permission to traverse a sparse gap.

## Segmented directional runs

The view stores maximal directed runs for E, NE, N, NW, W, SW, S, and SE. Runs
are ordered first by stable direction and then by start-node index. Every legal
directed edge occurs in exactly one run. E/W, N/S, NE/SW, and NW/SE propagation
therefore uses the same conservative source-owned edges as CPU A* across sparse
gaps, negative coordinates, and tile boundaries.

## Cost semantics

The header carries the normalized compiler heading mask and unsigned integer
orthogonal-step, diagonal-step, and bend costs. Hard illegality is absence of
an edge, never a large finite cost. A transition into direction `d` costs its
step cost plus the bend cost when the predecessor has another incoming
direction. The start sentinel pays no initial bend.

Both CUDA prototypes compute unsigned 64-bit labels. The compiler's existing
simple-state-path bound guarantees valid costs cannot overflow. The frontier
prototype uses deterministic integer cost buckets and duplicate-tolerant
relaxation. The sweep prototype computes heading-turn departure labels and
performs maximal segmented propagation for all four direction pairs. A bounded
run that has not converged reports budget exhaustion, not unreachable.

## Deterministic memory accounting

Schema v1 fixes these record sizes and verifies them with compile-time checks:

| Record | Bytes |
| --- | ---: |
| header | 112 |
| layer range | 48 |
| node | 56 |
| directional run | 12 |
| run-node index | 4 |

Persistent device bytes equal one header plus the size, not capacity, of every
layer, node, run, and run-node record. CUDA uploads every counted byte. Batch
bytes separately count the 56-byte device-produced result header, labels,
predecessors, 32-bit atomic active/frontier or departure scratch, and counters.
Telemetry reports persistent, batch, and peak owned bytes; peak must equal the
checked sum of the simultaneous persistent and batch tiers. It does not claim
whole-process or driver allocator usage.

## Untrusted result contract

Every readback contains a completion code, forced generator, endpoint node
indices, device-produced associations, full label and predecessor arrays, and
telemetry. Before any reached or failure completion is interpreted, the host
validates:

- array dimensions and every finite predecessor index;
- the start-only heading sentinel and unreachable-state sentinels;
- predecessor acyclicity, adjacency, heading, legal masks, and exact scalar
  cost reconstruction;
- stable minimum goal-state selection;
- board/profile/compiler/rule-bucket/device-view associations;
- exact coordinate reconstruction and exact swept geometry for all coalesced
  segments.
- finite nonnegative kernel time, execution-round bounds, required batch bytes,
  and checked persistent-plus-batch peak bytes.

Equal-cost CUDA geometry may differ from CPU A*, but reachability/failure
semantics and optimal scalar cost must agree. Repeated output must be identical
for the supported CUDA backend/device class. Through vias remain outside Phase
2 because no exact padstack feasibility provider exists yet.
