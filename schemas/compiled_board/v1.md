# CompiledBoard Contract v1

CompiledBoard v1 is the immutable, CAD-neutral M1 search view produced by
`apgar/geometry_compiler/compiled_board.h`. It is a disposable derivative of
an exact `BoardSnapshot`; it is never a legality authority.

## Association header

Every instance carries:

- the exact source Board IR `content_hash`;
- a compiler-profile fingerprint;
- geometry compiler version `1`;
- one prepared per-net M1 routing profile;
- the rule bucket derived from that retained profile and its stable identity;
  and
- compiler and logical-memory telemetry.

Consumers must reject an instance when its source hash, profile fingerprint,
compiler version, retained routing profile, or rule bucket does not match the
exact snapshot and routing request. Reuse across a changed board, compiler
profile, or routed net is invalid even if tile data looks plausible. Until a
consumer authenticates the retained routing-profile identity through its own
producer and admission contracts, it must fail closed for non-default Board IR
profiles.

Board IR v1 retains one default routing profile for source compatibility. The
default `CompileBoard` overload uses it. An explicit overload accepts a routing
profile only through `PrepareRoutingProfile`, which sorts allowed layers and
validates the net, exact two-terminal membership, dimensions, headings, and
layer availability against the immutable source snapshot. Every CompiledBoard
owns that prepared profile; it never borrows caller state.

## CompilerProfile v1

The profile is normalized before fingerprinting and publication. Exact
duplicate active regions are removed and the remainder are ordered by layer and
bounds. The public `FingerprintCompilerProfile` operation applies this
normalization to its own profile copy, so caller ordering and duplicate regions
cannot change the identity. The fingerprint is FNV-1a over a domain tag and the
following canonical field sequence, encoded with the Board IR stable-hash
integer conventions:

1. profile schema version (`1`);
2. signed 64-bit lattice origin `x`, `y`, and positive step;
3. unsigned 32-bit tile width and height in nodes;
4. inclusive compilation ROI minimum and maximum coordinates;
5. ordered layer-scoped inclusive active-region bounds;
6. M1 heading mask; and
7. unsigned integer orthogonal-step, diagonal-step, and bend costs.

Origins, ROI bounds, and active-region bounds must fit the Board IR exact
coordinate envelope. Tile dimensions are each in `[1, 4096]`. Active regions
must be non-empty, lie inside the explicit ROI, name an allowed rule-bucket
layer, and contain a lattice sample. Headings must be a non-empty subset of the
Board IR H/V/45 headings. Movement costs are deterministic integers and both
step costs are positive. Profiles whose deduplicated, layer-scoped active-region
union exceeds the M1 safety bound of 10,000,000 represented nodes, or whose
bounded state-path cost can overflow `uint64_t`, fail explicitly as
unrepresentable.

The ROI is not a board outline. CompiledBoard v1 does not infer or claim board
outline legality.

## M1 rule bucket

The rule bucket is derived only from the prepared routing profile retained by
the CompiledBoard:

- nominal trace width;
- clearance;
- sorted allowed layers; and
- allowed H/V/45 headings.

Its stable identity hashes those fields with the
`APGAR-M1-RULE-BUCKET-V1` domain tag. Fixture sizes and adapter defaults do not
participate except through their already-normalized routing-profile values.

## Sparse directional fields

A represented node is an integer lattice sample inside the union of active
regions for its layer. No node is created merely because it lies inside the
larger compilation ROI. Tiles are ordered by `(layer, tile_x, tile_y)` through
the `TileKey` comparison, and contain a sorted sparse vector of represented
row-major local node indices. Missing tiles and missing local indices consume
no node entry and are not traversable.

Each node has an eight-bit directed legality mask. Bit numbers and deterministic
neighbor order are:

| Bit | Direction | Lattice delta |
| --- | --- | --- |
| 0 | east | `(1, 0)` |
| 1 | north-east | `(1, 1)` |
| 2 | north | `(0, 1)` |
| 3 | north-west | `(-1, 1)` |
| 4 | west | `(-1, 0)` |
| 5 | south-west | `(-1, -1)` |
| 6 | south | `(0, -1)` |
| 7 | south-east | `(1, -1)` |

An edge is represented only when both endpoint nodes exist and its heading is
enabled. This includes edges whose endpoints are in different tiles. A mask bit
is set only after the existing exact movement oracle accepts the complete swept
trace envelope under the retained profile, including its net-specific obstacle
ownership semantics, on that layer. Diagonal edges use that same exact envelope
test; node occupancy or endpoint-only checks cannot create a corner-cutting
false-free edge. The compiler may exploit movement-oracle symmetry by testing
an undirected neighbor pair once, but it publishes both directed mask bits and
counts both in directed telemetry.

CompiledBoard v1 has no via mask, board-outline mask, portal, distance field,
incremental generation, or inferred transition legality.

## Telemetry

All edge counts are directed:

- `active_tile_count`: published sparse tiles;
- `represented_nodes`: stored sparse node entries;
- `represented_directional_edges`: enabled-heading neighbor relations whose
  endpoints are both represented;
- `legal_directional_edges`: represented edges published in masks;
- `blocked_directional_edges`: represented edges rejected by exact geometry;
- `false_blocked_directional_edges`: exact-legal represented edges withheld by
  an additional compiler-conservatism policy; and
- `false_blocked_rate_parts_per_billion`: false-blocked edges divided by all
  exact-legal represented edges, or zero when there are none.

The v1 compiler has no additional conservatism policy after exact testing, so
the false-blocked count is zero within represented fields. Sparse ROI gaps are
outside the represented-edge denominator and must be reported through active
region configuration/corpus coverage rather than misclassified as blocked
edges.

`estimated_host_bytes` is a deterministic logical-payload estimate. It equals
`sizeof(CompiledBoard)` plus the sizes, not capacities, of owned active-region,
rule-bucket-layer, retained-routing-profile-layer, sparse-tile, and
compiled-node vector elements. It excludes allocator metadata, spare vector
capacity, temporary compiler maps, and the source BoardSnapshot. This is
intentionally an estimate rather than a claim about allocator resident-set
size.

## CPU reference consumption

CPU A* uses stable east-through-south-east neighbor order, integer costs, and a
total queue key ending in a deterministic insertion sequence. Its state
includes incoming direction so bend cost is exact. Reconstructed adjacent
lattice points are coalesced into line segments, and every returned segment is
rechecked by exact geometry. A corrupted mask can therefore produce only a
structured validation failure, never a returned false-free route.

M1 requests retain distinct start and goal layers, but v1 adjacency is planar.
Different endpoint layers return `UnsupportedLayerTransition`; no permissive via
behavior is synthesized. Same-layer field disconnection is reported separately
from invalid requests and exact validation failures.
