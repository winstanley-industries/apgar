# Device Candidate Batch Contract v1

DeviceCandidateBatch v1 layers batched planar query/workspace/result records on
an unchanged DeviceCompiledBoard v1 prepared upload. Every batch references the
device-view fingerprint; it does not duplicate or mutate immutable board data.
The host classifies request-local invalid and unsupported queries before backend
discovery so an upload or metadata failure cannot erase those deterministic
per-query outcomes.

## Compatibility group

One backend execution contains only queries sharing Board IR, compiler profile,
compiler version, rule bucket, routing profile, device view, forced generator,
round/workspace limits, and supported backend/device class. Per-query endpoints,
query identity, seed, ordinal, bans, penalties, and objective surcharges may
differ. Incompatible queries receive explicit `Unsupported` or `InvalidInput`
results rather than being silently regrouped with changed semantics.
The compatibility envelope also carries deterministic device- and host-memory
budgets. Aggregate normalized policy resources across one v1 input batch are
bounded to 1,000,000 entries for queries admitted to device execution.
Host capacity, workspace, launch, and telemetry logic resolves the forced
generator through one exhaustive v1 descriptor. Unknown generator values have
no descriptor and are rejected explicitly; they never inherit sweep or
frontier behavior through a default branch.

## Query and policy encoding

Queries are sorted by unique nonzero 64-bit query identity. Each record repeats
batch identity, query identity, input ordinal, start/goal node, policy identity,
policy-array offset/count, workspace offset/count, round limit, and generator.
`input ordinal` is an opaque caller/list correlation value; it is not required
to equal the candidate policy's provenance `candidate ordinal`. Policy identity,
not input position, authenticates normalized policy semantics.
Canonical resource keys are resolved on the host to physical device-edge
indices. Each per-query edge adjustment is either a finite unsigned 64-bit
penalty or `UINT64_MAX` for banned.

The host/device ABI fixes these record sizes and verifies them with compile-time
assertions:

| Record | Bytes |
| --- | ---: |
| policy-edge adjustment | 16 |
| query | 120 |
| device-produced query result | 120 |

The query record includes separate workspace-state and frontier-state
capacities. The frontier explorer represents its bounded open set inside the
query-major state slice, so its explicit frontier capacity must cover that
slice; sweep records zero frontier capacity.

Every label, predecessor, frontier/closed/departure value, counter, and result
header is addressed through the query's checked disjoint workspace slice. A
device-produced result repeats the query identity and workspace owner. Host
validation rejects duplicate/foreign ownership, overlap, out-of-range offsets,
cross-query predecessors, and association drift before interpreting outcomes.
Device writers compare the expected workspace owner before label or
predecessor mutation; an ownership mismatch is stamped as an invariant failure
for that query instead of writing into a foreign slice.

## Frontier explorer

The batched frontier is a bounded deterministic heuristic A*-style explorer,
not a conventional global binary heap. Its admissible heuristic uses only
unavoidable movement costs. The stable winner key is
`(query identity, f cost, g cost, state index, incoming heading)`. Equal-cost
predecessors use the lowest stable predecessor state. Per-query state capacity,
rounds, workspace bytes, and batch bytes are explicit. One 256-thread block
cooperatively explores each query. A launch advances every still-running query
by at most 32 rounds before the host reads query statuses.

## Sweep explorer

The batched heading-aware sweep applies the same per-edge bans, penalties, and
objective surcharges while scanning compatible directional runs. A ban breaks
propagation at that physical edge. Convergence and budget exhaustion remain
distinct per query. Stable predecessor selection uses the same total state key
and policy cost semantics as CPU/frontier reconstruction. Departure labels are
computed over `(query, node, heading)` and directional runs are traversed over
`(query, run)` with deterministic unsigned atomic minima. The host dispatches
up to 8 sweep rounds between status readbacks.

## Deterministic memory accounting

Persistent device bytes belong to the prepared DeviceCompiledBoard upload and
are reported separately from the transient candidate batch. Let `Q` be the
query count, `P` the total policy-edge count, `S` the represented state count
per query, and `N` the represented node count. The v1 transient byte count is:

```text
Q * (120 query + 120 result + 4 status)
+ P * 16 policy edge
+ Q * S * (8 label + 4 predecessor + 8 state owner + 8 predecessor owner)
+ frontier: Q * S * 1 closed flag
+ sweep:    Q * N * 8 headings * 8 departure label + Q * 4 changed flag
```

All terms and the persistent-plus-batch peak are checked for unsigned 64-bit,
host-index, launch-dimension, and configured-memory-budget overflow before
execution. The CUDA backend sums the actual owned allocations independently
and rejects any disagreement with this formula.

Preparation also derives one trusted-host node lookup without changing the
serialized DeviceCompiledBoard v1 payload or its fingerprint. It is a canonical
vector of every 32-bit node index sorted by `(layer, lattice x, lattice y,
node index)`, so it occupies exactly `4 * N` logical bytes. Endpoint and policy
resource resolution binary-search this reusable lookup. The validated public
batch reports these bytes as `prepared_node_lookup_host_bytes`; they are
persistent prepared-view host ownership, not transient `batch_host_bytes` and
not backend/device telemetry.

Transient host ownership is bounded separately. Let `I` be the input query
count, `Q` the count admitted for device execution, `P` the policy-edge count
for those admitted queries, and `S` the represented state count per admitted
query. Before normalization, let `U` be the total banned-resource plus penalty
entry count across every individually shape-valid submitted policy. The first
host peak is checked allocation-free before any policy copy, sort, iteration,
or hash:

```text
I * (120 input query + 120 result + 128 fixed classification envelope)
+ U * 40 normalized-policy scratch
```

Normalization compacts each owned policy in place, so v1 needs one scratch
entry rather than simultaneous input and output scratch vectors. Forty bytes
is a checked layout upper bound for either `EdgeResourceKey` or
`ResourcePenalty`; compile-time assertions prevent implementation layout drift.
The later encode/execution/readback peak is:

```text
I * (120 input query + 120 result + 128 fixed classification envelope)
+ Q * (2 * 120 encoded/execution query + 2 * 4 status/partition)
+ P * (16 device policy edge + 40 normalized-policy retention)
+ Q * S * (8 label + 4 predecessor + 8 state owner + 8 predecessor owner)
```

The batch's deterministic host bound is the maximum of these two phase peaks,
not their sum, because normalization scratch has been released before the
encode/execution/readback phase. CUDA performs four bulk device-to-host
workspace transfers into final flat query-major label, predecessor, state-owner,
and predecessor-owner buffers. Each query envelope repeats its checked workspace
offset and state count, and host validation borrows the corresponding slices
through bounded non-owning views. No per-query partition copy or validation copy
is retained.
Allocator bookkeeping is intentionally excluded. The host
first checks the allocation-free minimum `I`-query classification/result
envelope before allocating uniqueness, output, or admission bookkeeping. It
then sums `U`, the submitted resource-entry counts of every individually
shape-valid policy using checked wide arithmetic. If that aggregate exceeds
1,000,000, the whole batch returns one outer `ResourceExhausted` outcome before
any valid policy is copied, sorted, iterated, or hashed. Individually
over-limit policy shapes do not contribute to that aggregate; when the valid
aggregate fits, they remain cheap query-local `InvalidInput` outcomes. These
two outer failures are the explicit peer-preservation exceptions: retaining
one result per input or deriving every valid policy identity would itself
exceed the declared envelope/work bound. Once both preflights pass, the host
normalizes each independently valid policy, retains its identity, and
classifies invalid, unsupported, off-lattice, or unrepresented requests before
backend discovery.
It then checks the complete formula: small classification/result envelopes are
charged to all `I` inputs, while policy and workspace terms are charged only to
the `Q` admitted queries. Execution
telemetry reports the all-admitted (`I == Q`) backend-owned subset. A normalized
count above the already-checked submitted aggregate, arithmetic overflow, or
configured host-budget violation marks otherwise admitted queries
`ResourceExhausted` while preserving already-classified invalid and unsupported
peers. Peer preservation therefore begins only after both outer preflights are
affordable. If none remain
admitted, backend discovery does not occur and an already prepared execution
does not inspect its prepared view. An unavailable or association-mismatched
prepared view is a shared execution failure applied only to admitted queries;
preflight-classified peers retain their original outcomes. Host allocation
failure is also reported as `ResourceExhausted`, never as an exception escaping
the API.

## Telemetry ownership and validation

Shared execution telemetry is carried once on the outer batch result:

- persistent prepared-upload bytes;
- transient batch bytes and simultaneous peak owned bytes;
- deterministic transient host bytes;
- CUDA-event milliseconds for the initialization-through-predecessor-selection
  execution envelope;
- exact kernel-launch count;
- exact blocking query-status readback count;
- exact shared rounds dispatched plus a zero-or-one unfinished-query
  finalization-launch count; and
- the generator chunk size, exactly 32 for frontier and 8 for sweep.

The launch count includes initialization, every dispatched frontier chunk or
sweep-round kernel, optional unfinished-query finalization, and stable
predecessor selection. It excludes transfers; blocking status transfers are
counted separately. A sweep round omits its run kernel only when the prepared
board has no directional runs.

Outer launch/readback validation is derived exclusively from these validated
shared dispatch fields. It never derives a batch-wide expectation from an
unvalidated query completion or round header, so one corrupt query cannot poison
an otherwise valid peer.

Per-query telemetry contains only query-local examined work, heading-turn
relaxations, and rounds. It never repeats shared memory, launch,
synchronization, or timing values. The host validates the outer envelope once
against the deterministic allocation and launch schedule, then validates each
query's telemetry against its own header, completion state, round limit, and
work bounds. Corrupt outer telemetry invalidates the admitted batch; corrupt
query telemetry invalidates only that query. The legacy single-route API may
combine an internally delegated batch-of-one envelope with its sole query's
work fields to preserve its pre-batch `KernelTelemetry` contract.
When that API clones an immutable sealed route into its owned legacy result,
host allocation or container-capacity failure is translated to the
`resource-exhausted` outcome rather than escaping as an exception.

The public host result exposes each query outcome through
`PlanarCandidateBatchItem`. Public construction and mutation helpers create
only unsealed diagnostic state. After batch/query association, ownership,
telemetry, predecessor, policy, reconstruction, and exact route checks succeed,
the host moves a reached result into a separately allocated, truly const
evidence snapshot bound to the batch schema version and batch identity. Copies
share that immutable snapshot and public mutation attempts fail. Failure items
are intentionally unsealed. A second evidence bit records whether the prepared
view passed the always-linked core's exact-final-type check for the privately
constructed CUDA wrapper. Generic backends and wrappers cannot acquire it even
when they forward to CUDA or report identical metadata. Public outer-batch
fields remain serialized consistency context; they substitute for neither host
validation nor concrete producer authentication.

The authenticated CUDA preparation API returns `unsupported` with invariant
`gpu.producer.authentication.v1` when the supplied backend is not the exact
final privately constructed CUDA wrapper. Generic preparation remains valid
for routing, differential testing, and failure decoration, but its reached
items are not eligible to mint CUDA RouteCandidate provenance.

## Outcomes, cancellation, and determinism

Each query independently reports reached, unreachable, unsupported, invalid,
resource-exhausted, cancelled, backend-failure, validation-failure, or
internal-invariant plus query-local work and rounds.
One query's ordinary failure does not overwrite another result. A backend-wide
failure may fail every unfinished query while preserving already validated
partial results in query order.

`Disconnected` is accepted only after structural validation and independent CPU
A* confirmation under the identical normalized candidate policy. If CPU A*
reaches the goal, the GPU result is rejected with stable invariant identity
`gpu.disconnected.cpu_reachable.v1`; labels with infinite goal states are not a
negative reachability certificate. The exported untrusted-result validator also
normalizes and enforces every request policy ban, penalty, and surcharge and
emits the normalized policy identity, including for the default policy.

Cancellation is sampled at bounded batch chunk boundaries: after no more than
32 frontier rounds or 8 sweep rounds. Queries not yet complete become
cancelled; completed results retain their outcome. Repeating an identical batch
must return identical ordered results and deterministic telemetry other than
elapsed CUDA-event time on the supported backend/device class.
