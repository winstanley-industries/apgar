# Device Candidate Batch Contract v1

DeviceCandidateBatch v1 layers batched planar query/workspace/result records on
an unchanged DeviceCompiledBoard v1 prepared upload. Every batch references the
device-view fingerprint; it does not duplicate or mutate immutable board data.

## Compatibility group

One backend execution contains only queries sharing Board IR, compiler profile,
compiler version, rule bucket, routing profile, device view, forced generator,
round/workspace limits, and supported backend/device class. Per-query endpoints,
query identity, seed, ordinal, bans, penalties, and objective surcharges may
differ. Incompatible queries receive explicit `Unsupported` or `InvalidInput`
results rather than being silently regrouped with changed semantics.

## Query and policy encoding

Queries are sorted by unique nonzero 64-bit query identity. Each record repeats
batch identity, query identity, input ordinal, start/goal node, policy identity,
policy-array offset/count, workspace offset/count, round limit, and generator.
Canonical resource keys are resolved on the host to physical device-edge
indices. Each per-query edge adjustment is either a finite unsigned 64-bit
penalty or `UINT64_MAX` for banned.

Every label, predecessor, frontier/closed/departure value, counter, and result
header is addressed through the query's checked disjoint workspace slice. A
device-produced result repeats the query identity and workspace owner. Host
validation rejects duplicate/foreign ownership, overlap, out-of-range offsets,
cross-query predecessors, and association drift before interpreting outcomes.

## Frontier explorer

The batched frontier is a bounded deterministic heuristic A*-style explorer,
not a conventional global binary heap. Its admissible heuristic uses only
unavoidable movement costs. The stable winner key is
`(query identity, f cost, g cost, state index, incoming heading)`. Equal-cost
predecessors use the lowest stable predecessor state. Per-query state capacity,
rounds, workspace bytes, and batch bytes are explicit.

## Sweep explorer

The batched heading-aware sweep applies the same per-edge bans, penalties, and
objective surcharges while scanning compatible directional runs. A ban breaks
propagation at that physical edge. Convergence and budget exhaustion remain
distinct per query. Stable predecessor selection uses the same total state key
and policy cost semantics as CPU/frontier reconstruction.

## Outcomes, cancellation, and determinism

Each query independently reports reached, unreachable, unsupported, invalid,
resource-exhausted, cancelled, backend-failure, validation-failure, or
internal-invariant plus query-local work, rounds, memory, and kernel timing.
One query's ordinary failure does not overwrite another result. A backend-wide
failure may fail every unfinished query while preserving already validated
partial results in query order.

Cancellation is sampled at bounded batch launch boundaries. Queries not yet
complete become cancelled; completed results retain their outcome. Repeating
an identical batch must return identical ordered results on the supported
backend/device class.
