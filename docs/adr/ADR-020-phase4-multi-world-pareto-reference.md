# ADR-020: Phase 4 Fixed-Pool Multi-World CPU Reference

**Status:** Accepted for the sixth Phase 4 vertical slice
**Date:** July 20, 2026
**Applies to:** Deterministic negotiated-price branching, bounded Pareto
retention, and retained-world CandidateStore ownership

## Context

ADR-015 through ADR-019 established authentic multi-net pools, a deterministic
One-World CPU reference, bounded negotiated prices, and one complete targeted-
regeneration execution. Multi-world work must now define independent state
lineage, comparable board outcomes, deterministic retention, and candidate
ownership before GPU execution or evidence experiments can use world count as
a meaningful variable.

Interleaving regeneration immediately would make publication order semantic:
one world could observe columns generated by an earlier world while another
remained on the old pool. Solving that problem requires an explicit global
epoch barrier rather than hiding scheduler order inside the first multi-world
reference.

## Decision

- Adopt `schemas/allocator/multi_world_execution_v1.md`.
- Execute every schedule against one fixed, complete, authentic Multi-Net
  Workload candidate-pool snapshot and one common authenticated Negotiated
  Price state. Schedules vary a nonzero search intrinsic-cost weight and a
  bounded selection-round count. Distinct nonzero keys establish canonical
  order; duplicate keys and duplicate exact v1 schedules are rejected.
- Copy common pool handles once per schedule. Run production One-World and
  Negotiated Price primitives without reinterpretation. A branch never
  consumes another branch’s state. Stop at feasibility, a missing-candidate
  outcome requiring regeneration, or the exact declared round limit.
- Bound all known proportional work before bulk copying using widened products.
  Charge one fixed source-authentication pass, every explicit selection pass,
  and the hidden One-World reconstruction inside every price update.
  Candidate/span/resource/net work uses that same declared pass count in
  preflight and runtime counters. Reject inconsistent round/update tuples,
  including every zero-world tuple other than zero rounds and zero updates.
  Stage hostile-source preflight: validate the store and pool count first,
  validate every One-World limit plus the exact capacity/price input count,
  shallow-count candidates without dereferencing them, and stop span/expanded-
  edge accumulation at the first record that proves either the One-World or
  charged-work cap cannot fit. Over-cap suffixes are never traversed.
  Bound aggregate full terminal state buffered before dominance separately
  from exact retained world, selection, resource, price, and unique-winner
  records. A Pareto frontier that exceeds retention bounds fails rather than
  being silently approximated.
- Treat worlds within declared missing-net and overuse thresholds as Pareto
  eligible. Retain every nondominated terminal world under selected nets
  maximized, overuse minimized, and common unweighted candidate intrinsic cost
  minimized. Equal points remain. Separately identify the lexicographically
  preferred retained world required by the Phase 4 evidence decision.
- Keep compact summaries and complete round/state/world checksum traces for all
  branches. Retain complete final price states and One-World allocations only
  for the Pareto archive.
- Reject incomplete/duplicate pool rosters and candidate net, association, or
  exact workload endpoint-coordinate/layer mismatches as malformed source
  input. Then atomically acquire one full-
  source-pool CandidateStore lease before the production source-authentication
  selection. Before releasing it, atomically recompare the complete pool
  snapshot and acquire one successor lease over the union of retained winners.
  Empty winner sets retain an active store-identity lease. CandidateStore drift
  prevents result publication.
- Return resource-refinement-required without executing branch worlds or
  claiming feasibility when a known exact conflict is absent from the resource
  vocabulary. Still lease and authenticate the source snapshot, and charge
  that fixed source pass.
- Bind the source snapshot, branch state, all configuration, canonical
  schedules, traces, outcomes, retention decisions, preferred world, counters,
  and retained state/world checksums into stable versioned replay identities.

## Consequences

- The CPU reference can independently reproduce tens or hundreds of compact
  allocator worlds without duplicating candidate geometry or pathfinding state.
- Search weights may differ while retained quality remains comparable because
  dominance uses unweighted intrinsic candidate cost rather than negotiated
  selection score.
- CandidateStore pruning cannot detach a retained world, and a concurrent pool
  mutation cannot silently change which immutable snapshot was evaluated.
- The Pareto archive and the lexicographic evidence choice are explicit,
  separate concepts consistent with ALL-002 and Section 29.2.
- This slice does not publish columns. Multi-world regeneration requires a
  later freeze/gather/canonical-CAN-004/refresh epoch contract.
- GPU multi-world execution, the versioned Phase 4 corpus, equal-budget
  comparison, combined exact legality, legalization, and host-CAD validation
  remain outside this decision.
